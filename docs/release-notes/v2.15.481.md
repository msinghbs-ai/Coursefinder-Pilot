# v2.15.481 — Intake recovery: the calendar year from its own section

Platform Admin mandate 5 Nov 2026 12:44 (final intake recovery strategy and self-sustainability acceptance).

## What changes

- The calendar reader takes a start's year from the section it sits in (heading, document title or year tabs above repeated term blocks). A year from another section is rejected; a start with no provable year is never given one.
- Stored calendars are read again when the reader changes, only where intake rows of the top Australian universities still miss a date.
- Every unfinished intake row carries a durable reason and the change that brings it back; deterministic failures are not repeated on a timer.
- Admitted intake values are checked against the Website API v2 source.
- Old calendar editions can be refreshed through the existing source reads, at most 40 Firecrawl credits in total, with credits and yield recorded.
- Process results shows the recovery: admitted and published by university, source, year and precision; skipped and failed by reason with the next look; refresh credits and yield.

## Not changed

The consumer API (Website API v2, Zoho) is unchanged. No new job, engine, controller or screen. No global concurrency or spend setting is changed.
