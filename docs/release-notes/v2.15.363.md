# PIM Admin v2.15.363 — Entry requirements workspace

Date: 29 Oct 2026
State: release candidate (v2.15.79 remains the accepted recovery release)

## Changes

- **Catalogue › Entry requirements** is a new menu page beside Scholarships. It has four views:
  - Provider entry matrix;
  - Course entry requirements;
  - Sources, reads and holds;
  - Resolution inspection.
- **Summary:** above each view, counts of active rows, rows waiting in Layer 4, quarantined rows, withdrawn rows, held sources and courses with requirements, all with words, not colour alone.
- **Lists:** combined filters with chips and Clear filters, sorting, 50 rows a page and a Columns menu. They use the same table and drawer as the catalogue.
- **Drawer:** the full quote, the source and its stored copy, the reading run, the Layer 4 item, and the history of every change by a person (before, after, who, when and why).
- **Edit in list (Curator and above):**
  - A reason is asked once per editing session and kept with each change.
  - A change to a row someone else changed since it was opened is refused.
  - A band, minimum or value that the quote does not print is refused.
  - Conditions are edited as parts, never as raw data.
- **Add requirement:** from the provider's own source and its stored copy.
- **Withdraw, Quarantine and Restore:** each with a reason. There is no delete and no bulk action.
- **Waiting AI rows:** never edited or activated here; they link to Layer 4.
- **Sources, reads and holds:**
  - each source's stored copy, latest read, cost, rows not kept and why;
  - Read again for one source (Platform Admin, with a reason). A source held as unreadable is not read again.
- **Resolution inspection:** for a course and a country, which of the five rules applied and why the earlier ones did not.
- **Provider drawer and Course detail sections:** they stay read only and open the workspace.
- **Consumer API:** unchanged.
