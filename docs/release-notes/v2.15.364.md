# PIM Admin v2.15.364 — Course-level reading, the rendered no-table note and HTML refetch

Date: 29 Oct 2026
State: release candidate (v2.15.79 remains the accepted recovery release)

## Changes

- **Course-level reading** is a new panel in Catalogue › Entry requirements › Course entry requirements. For each provider in the plan it shows:
  - the courses that can be read (a stored official page and strong identity);
  - courses read, reading, waiting in Layer 4, admitted, with no row kept, and remaining;
  - the estimated cost left.
- **Above the table:** the cost a course (measured once 20 reads are measured, an estimate until then), the OpenRouter balance against its floor, and the batch size.
- **Batches (Platform Admin):**
  - Preview next batch shows how many courses the next batch would read (next by priority, or one provider) and its estimated cost.
  - Read next batch asks for it, with a reason.
  - A batch is at most the set number of courses and never includes a course already read.
  - A batch is refused while an earlier course read waits, when AI is stopped, or when it would take the balance below its floor.
  - Every course read goes to Layer 4.
- **Rendered page with no requirements table:**
  - It now waits in Layer 4 as a note, shown as "Rendered, no table: in Layer 4".
  - Once approved it shows as "No matrix published (confirmed)".
  - Approving the note admits and replaces nothing.
- **Read again on a web page stored as markdown:** the page is fetched again as HTML, and the markdown copy stays as evidence. Its waiting rows and Layer 4 item are superseded first, with the reason.
- **Entry matrices:** slices of a long page are read six at a time, 8,000 characters a slice. Both are settings in Settings › Pipeline settings › Entry requirements.
- **Consumer API:** unchanged.
